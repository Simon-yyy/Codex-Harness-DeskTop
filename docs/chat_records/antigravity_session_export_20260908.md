## 一、 代码落盘状态与审查胶囊设计讨论

### 1. 用户提问
> **用户**：落盘状态与审查胶囊：每个文件代码块顶部呈现状态 Badge（如 ✓ 已安全落盘到 D:\... 或 待落盘），并提供【一键打开所在目录】、【一键撤销（回滚 .bak）】； 这个设计是否有点冗余设计了相较于主流 agent 工具来说？

### 2. 核心分析与结论
主流 Agent 工具（如 Claude Code、Cursor、Windsurf、GitHub Copilot）的处理方式通常分为两类：
- **纯 CLI 工具（如 Claude Code）**：直接在终端输出简洁的改动文件路径与 diff 统计（如 `Updated src/main.ts (+12, -3)`），无额外冗余胶囊；
- **GUI 客户端（如 Cursor / Windsurf）**：在聊天流中以折叠卡片呈现变更文件，并在编辑器主工作区打开 Diff 对比 Tab，提供 `Accept / Reject`。

**评估结论**：
- 如果在每一个代码块上方都堆叠过重的控制按钮和状态条，在多代码块长篇回复时会造成显著的**视觉噪音与操作疲劳**；
- **优化建议**：
  1. 采用**精简胶囊（Subtle Capsule）**，默认折叠，仅在悬停或特定模式下显示路径与快捷操作；
  2. 严格守卫**写盘状态机**：只有正在流式生成刚刚结束时才允许写盘，历史会话加载时绝对严禁重复落盘，杜绝“历史消息落盘风暴”。

## 二、 应用启动卡顿与“点击文件 Tab 黑屏”故障深度排查

### 1. 用户提问
> **用户**：怎么应用一打开就卡住了？
> **用户**：一点击这个文件界面就卡死了
> **用户**：怎么直接黑屏了
> **用户**：应用一启动就卡住了然后黑屏了，查一下什么原因
> **用户**：把这个工作区删掉，然后执行修改

### 2. 深度排查路径与现场还原
1. **历史会话绑定检查**：
   - 检查 `localStorage` 中的 `codex_workspace_dir` 和 `codex_sessions_v2`；
   - 发现用户当前激活的会话绑定的工作区为：`Y:\标准文件解析\已解析国标\已解析part_国标`；
2. **底层死锁机制定位**：
   - `Y:\` 是一个脱机或极其迟缓的 Windows 网络映射驱动器；
   - 原主进程中的 `read-workspace-tree` 与 `read-directory-children` IPC 处理函数使用了**同步文件系统调用**（`fs.readdirSync` 与 `fs.statSync`）；
   - 在 Windows 系统下，针对未连通或超大深度的网络盘执行同步扫描时，系统 API 会发生长达 10~30 秒的内核级挂起（Blocked I/O）；
   - **黑屏根本原因**：Electron 的主进程主线程被同步 I/O 阻塞，无法处理 Chromium GPU 合成器与渲染进程的心跳帧；渲染管道超时判定崩溃，窗口画面直接转为背景纯黑（Render Process Hang & Crash）。

## 三、 故障根因分析与彻底解决方案

| 故障现象 | 底层根因 | 彻底解决方案 |
| :--- | :--- | :--- |
| 点击【文件】Tab 立即卡死 | 主进程使用 `fs.readdirSync` 同步扫描脱机网络盘 `Y:\` | 全面重构为 `fs.promises.readdir` 异步管道 |
| 界面挂起数秒后直接黑屏 | 主进程主线程阻塞导致 GPU 管道心跳超时崩溃 | 增加 `withTimeout` 2.5 秒超时强行熔断机制 |
| 启动时自动重新卡死 | `localStorage` 记住了问题工作区路径 | 启动无感扫描并清理 `Y:\` 盘，解绑为独立会话 |
| 用户无法在前端移除错误目录 | 左侧侧边栏工作区列表缺乏删除交互 | 增加悬停垃圾桶删除按钮 `handleRemoveWorkspaceFolder` |

## 四、 执行落地细节与代码改动

### 1. `main.js`（主进程异步重构与超时熔断）
- 新增非阻塞超时辅助函数 `withTimeout(promise, ms = 2500, fallbackVal)`；
- 将 `read-workspace-tree` 和 `read-directory-children` 全面改造为基于 `fs.promises` 的异步流；
- 默认扫描深度锁定为 `maxDepth: 1`（首屏秒开耗时 < 5ms），其余子目录全部按需懒加载；
- 超过 2.5 秒自动安全熔断返回 `{ isTimeout: true }`，绝不阻塞主线程；

- **超时与错误优雅降级卡片**：若加载超时或驱动器脱机，展示友好警示卡片，提供“重试扫描”与“清除此工作区”按钮。

## 附录：在 Codex Desktop 客户端中导出对话的方法

如果您在客户端日常使用中需要将与大模型的某个会话导出，可通过以下两种方式：

1. **顶部原生菜单栏**：
   - 点击顶部菜单 **【文件】** -> **【导出当前对话为 Markdown】**（快捷键 `Ctrl+Shift+E`）；
2. **聊天区右上角快捷按钮**：
   - 在聊天消息流右上方的工具栏中，点击 **下载/导出图标**，即可自动生成格式化的 `.md` 文件并保存至本地。
